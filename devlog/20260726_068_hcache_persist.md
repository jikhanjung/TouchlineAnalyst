# 068: rotcam 이송 H 디스크 캐시 — C0011 전환 17초 해소

- 날짜: 2026-07-26
- 종류: 최적화
- 관련: [063](20260726_063_pitchwatch_fixes_and_anchors.md) (확정 앵커),
  [067](20260726_067_infield_filter.md)

## 증상

멀티캠 경기에서 C0011(rotcam) 컨텍스트 전환 시 "목록/이벤트 표시 갱신"
이 **16.8s** (pano 는 수 초). 사용자 로그 타임스탬프로 특정.

## 원인

`_show_frame` → `_rc_transfer_landmarks` 가 랜드마크 소스 프레임들을
현재 프레임으로 이송하는데, 프레임쌍마다:
1. **원본 네이티브 디코드** — 27GB 4K 파일 빠른 시크도 ~1.5-3s/장,
   소스 프레임 6~10개
2. **SIFT 매칭 + 호모그래피** — 1600px 쌍당 ~0.3-0.6s

세션 내에는 `_Hcache` 로 캐시되지만 열 때마다 리셋 → 매 전환마다 전부
재계산. 전부 GUI 스레드(대기 커서만 표시).

## 수정

**H 캐시 사이드카 영속화** (`.ptz_hcache.npz`) — 영상이 불변이라
(src,dst)→H 는 세션 간에도 영구 유효:

- open 시 `_Hcache = {}` 리셋 대신 디스크 로드. **실패쌍(None)도 저장**
  — 안 그러면 매칭 안 되는 먼 쌍을 열 때마다 재시도(디코드+SIFT).
- 저장: `_rc_transfer_landmarks`/`_refit_field_rotcam` 끝에서 신규 항목
  있을 때만 (수 KB, savez_compressed). detw(매칭 해상도) 불일치 시 무효.
- 관측성: 이송이 0.5s 넘으면 "[rc] 랜드마크 이송 N개 — Xs (신규
  프레임쌍 SIFT, 결과는 캐시됨)" 로그.

효과: 최초 1회만 SIFT 비용을 내고, 이후 열기/전환은 **디코드·SIFT 없이
캐시 히트** (top_black 캐시와 같은 '한 번 열면 저장' 원칙). 스크럽으로
새 프레임에 갈 때의 근접-앵커→현재 쌍만 신규 비용.

## 검증

npz 라운드트립 (성공쌍·실패쌍·detw 게이트) 재현 테스트 통과, 3쌍
621bytes. 실기 재열기 체감은 Windows 재실행에서 확인 예정.
