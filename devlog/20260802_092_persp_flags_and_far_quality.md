# 092 — 원근 보정 플래그(k/m/widen) + 원경 화질 실측

2026-08-02. devlog 091 의 분석을 실제 플래그로 넣고, 넣기 전에 "k/m 을 키우면
**원경 화질**은 어떻게 되나"를 측정했다. 결론부터: **확대는 되지만 디테일은
안 는다. 오히려 리샘플링 손실만큼 준다.**

## 원경 화질 실측 (scale=1.0, pano_0001)

091 의 비교는 `scale=0.3` 프리뷰라 화질 판단에 못 쓴다. 실제 해상도
(5976×2306)로 다시 렌더하고, 먼쪽 터치라인 위 선수 줄을 각 변형의
**네이티브 픽셀로** 잘라 비교했다.

먼쪽 터치라인 = **행 329, el −2.73°** (091 의 scale=0.3 실측 −2.77° 와 일치).

> 처음엔 수평선 위(행 198, el +1.55°)의 펜스/건물 라인을 잡아 k 배율이
> 1.00 으로 나왔다 — **k 는 수평선 아래에만 적용된다**(`below = y_mid >
> horizon`). 측정 창을 수평선 아래로 제한해 바로잡았다.

| 설정 | 크롭 | 확대 | 정규화 선명도 |
|---|---|---|---|
| k=0.00 m=1.00 | 840×150 | 1.00× | **294** |
| k=0.30 m=1.00 | 840×197 | 1.31× | 249 (−15%) |
| k=0.45 m=1.00 | 840×234 | 1.56× | 252 (−14%) |
| k=0.30 m=1.30 | 1049×236 | 1.57× | 201 (−32%) |

정규화 선명도 = 같은 내용을 공통 크기(840×150)로 되돌린 뒤 Laplacian
분산. **확대가 진짜 디테일을 만들면 이 값이 유지된다.** 유지되지 않고
15~32% 떨어진다 = 순수 리샘플링이고, 왕복 보간 손실만 남는다.

- **k 단독은 −15%** 에서 평탄하다 (0.30 249 → 0.45 252). 세로 한 축만
  리샘플링해서다.
- **m 을 얹으면 −32%.** 가로까지 리샘플링하니 손실이 두 배.

원경 선수 신장은 여기서 **약 36px** (1.7m / 82.7m × f 1754). `--min-h 90`
이 원경을 못 잡아 `_FarTracker` 네이티브 타일을 쓰는 이유가 이 숫자다.
파노라마를 확대해도 **소스 정보량은 그대로**라 검출 측면에서 네이티브
타일 경로가 여전히 정답이다 — k/m 은 **사람 눈 가독성** 개선이지 분석
개선이 아니다.

## 넣은 플래그

```
--persp-k K        세로 리맵 강도 [0,1)   (권장 0.3)
--persp-m M        키스톤 최상단 배율 (1=없음, 권장 1.3)
--persp-widen 배율  키스톤 캔버스 확장 (권장 1.15, m>1 일 때만 유효)
```

기본값은 `0.0 / 1.0 / 1.0` — **기존 동작 무변경**.

### 캔버스 확장 (091 의 "코너 잘림" 해결)

`build_perspective_maps(..., src_w=None)` 로 **출력 폭과 소스 폭을 분리**
했다. 상단 행의 가로 배율이 `1/m` 이라, 출력이 소스와 같은 폭이면 상단
좌우가 `1-1/m` 만큼 잘린다. `w = src_w*m` 으로 넓히면 상단이 온전히 남는다.

`Renderer(persp_widen=)` 가 이걸 쓴다. 실측 (scale=0.3, k=0.30 m=1.30):

| widen | 출력 | 하단 빈 화소 |
|---|---|---|
| 1.00 | 1792×692 | 5.4% (기존 auto-el 코너) |
| **1.15** | **2060×692** | **17.5%** |
| 1.30 | 2328×692 | 27.0% |

`1 - 1/1.3 = 23%` + 기존 코너 5.4% ≈ 28% 로 이론과 맞는다. 행마다 가로
배율이 다르므로 **직사각형 출력에서 상단 보존과 하단 채움을 동시에
만족하는 폭은 없다** — 어디서 끊을지만 고르는 문제다.

### 그 밖에

- **borderMode 를 REPLICATE → CONSTANT(-1) 로.** 넓힌 캔버스의 빈 쐐기가
  소스 밖을 가리켜야 하는데 REPLICATE 면 가장자리 화소가 쐐기로 번진다.
  widen=1 에서는 맵이 소스 범위를 안 벗어나므로 기존 동작과 동일하다.
- **프리뷰에도 k/m/widen 반영** (`_level_preview`). 여기서 눈으로 보고
  중단을 판단하는데 투영이 다르면 확인 의미가 없다.
- **사이드카에 투영 파라미터 기록** — `.pystitch.json` 의 `user` 에
  `persp_k/persp_m/persp_widen`. 파노라마 픽셀 좌표계가 이 값에 달려
  있어, 나중에 field 캘리브·랜드마크를 해석하려면 필요하다 (091 에서
  "버전을 박아야 안전하다"고 한 부분).
- **인자 검증을 argparse 직후로.** 경기장 이름과 같은 이유 — 몇 시간
  인코드한 뒤 Renderer 에서 터지면 늦다.
- NVENC 폭 한계는 걸리지 않는다: 5976 × 1.30 = 7769 < 8192(hevc). 넘겨도
  `export.py:156` 폴백이 받는다.

`tests/test_perspective_widen.py` 7건 — src_w 생략 시 기존 맵과 바이트
동일 / widen=m 상단 전폭 보존 / widen=1 상단 `1/m` 만 남음 / 하단이 소스
밖을 가리킴(쐐기 비율 `1/m`) / 심 중앙 고정점 / m=1 인데 widen>1 이면
ValueError / widen 은 폭만 바꾸고 높이 불변. 전체 182건 통과.

## 쓰는 법

```powershell
python main.py --headless <L> <R> --auto-el --stitch-only `
  --persp-k 0.30 --persp-m 1.30 --persp-widen 1.15
```

## 주의 — 기존 산출물과 섞지 말 것

투영을 바꾸면 **파노라마 픽셀 좌표가 바뀐다.** 이미 `field_points` 캘리브나
`.ptz.json` 랜드마크가 있는 영상에 다른 k/m/widen 으로 재스티칭하면 그
편집들이 어긋난다. 새로 찍는 것부터 적용하고, 기존 영상은 사이드카의
`persp_*` 값을 그대로 유지할 것.
