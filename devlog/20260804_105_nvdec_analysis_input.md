# 105 — 분석 입력을 NVDEC 으로: wall +8.8%, CPU −48%

2026-08-04. 재분석 배치(100시간+)를 겨냥해 분석 입력 디코드를 NVDEC 으로
옮겼다. 스티칭에서는 NVDEC 이득이 전송에 먹혔지만(devlog 101) **분석은
다르다** — 3프레임 중 1장만 내리므로 이득이 남는다.

## 디코드 단독 (pano_0001, 5976×2306 hevc, 3000프레임, detect_every=3)

| | fps | CPU | 코어 |
|---|---|---|---|
| CPU (현행) | 51.5 | 221.8s | **3.81** |
| **NVDEC + 3프레임마다 다운로드** | **109.2** | **27.3s** | **0.99** |
| NVDEC GPU 상주 (참고) | 229.1 | 7.4s | 0.57 |

**wall 2.1배, CPU 8.1배.** 6K hevc 소프트 디코드는 프레임당 74ms 로 비싸다.

## 분석 종단 (YOLO 포함, 900프레임)

| | fps | CPU | 코어 |
|---|---|---|---|
| CPU 디코드 | 12.54 | 127.2s | 1.77 |
| **NVDEC** | **13.64** | **65.7s** | **1.00** |

**wall +8.8%, CPU −48%.** 디코드가 분석 시간의 ~24% 라 wall 이득은 그만큼만
남고, **진짜 성과는 CPU 절반**이다.

디코드 단독 2.1배가 종단 8.8% 로 줄어드는 건 devlog 101 에서 본 것과 같은
구조다 — 파이프라인 종단은 개별 단계 이득을 그대로 받지 않는다. 다만
이번엔 **CPU 절감이 별도로 남는다**는 게 다르다.

## 구현 — `core/gpudecode.py` 의 `FrameSource`

`cv2.VideoCapture` 의 `grab`/`retrieve`/`seek_frame`/`get`/`release` 를
그대로 흉내내는 얇은 껍데기다. 분석 루프는 한 줄도 안 바뀐다.

```python
cap = FrameSource(path, log=log)      # NVDEC 있으면 쓰고 없으면 CPU
```

- **`grab()` 은 GpuMat 을 들고만 있고 `retrieve()` 에서 내린다** — 버리는
  2/3 프레임은 GPU 를 떠나지 않는다. 이득의 원천이다
- 체크포인트 재개는 `seek_frame()` → cudacodec 은 `firstFrameIdx` 로 재오픈
  (프레임 정확, devlog 094 검증)
- `PYSTITCH_NVDEC=0` 으로 끌 수 있고, CUDA OpenCV 가 없으면 **조용히 CPU**
- `OPENCV_FFMPEG_READ_ATTEMPTS` 를 import 시점에 올린다 — 부가 스트림 때문에
  디먹서가 EOF 와 구분 안 되는 False 를 내는 사고(devlog 094) 예방

## ⚠️ 색차 — 한 파일 안에서 디코더를 섞지 말 것

cudacodec 의 BGR 변환은 CPU 디코더와 다르다. 파노라마 실측:

| | 값 |
|---|---|
| BGR PSNR | 42.6dB (평균차 1.34, 최대 20) |
| HSV 평균차 | H **1.22** / S **3.63** / V **2.60** |

팀 분류는 트랙릿 **간** 상대 색으로 군집하므로 전역 이동은 사실상 무해하다.
다만 `.analysis.json` 에 기록되는 값이 달라지므로 **`--far-augment` 는
원본과 같은 백엔드**를 써야 한다 (한 파일 안에 두 디코더의 색이 섞이면
군집이 흔들린다).

## 검증

`tests/test_gpudecode.py` 7건 — CPU 폴백이 `VideoCapture` 와 **프레임 단위로
동일**(분석과 같은 grab-all/retrieve-Nth 패턴), 시크가 같은 프레임에 착지,
메타 조회, 없는 파일 예외, `PYSTITCH_NVDEC=0`. NVDEC 있는 환경에서는 프레임
정렬 일치까지 확인(색차 때문에 비트 비교 대신 평균차 문턱). 전체 216건 통과.

## ⚠️ 배포 조건 — 현재 프로덕션에선 못 쓴다

NVDEC 경로는 **CUDA 빌드 OpenCV** 가 있어야 한다 (devlog 093). Windows
프로덕션 환경(conda PyStitch360)에는 없고, 넣으려면 CUDA Toolkit 13.1 +
win 용 CUDA wheel 이 필요하다. 코드는 자동 폴백하므로 지금 그대로 둬도
안전하지만, **효과를 보려면 환경 작업이 선행되어야 한다.**

WSL 에서는 이미 스크래치 환경으로 동작을 확인했다.
