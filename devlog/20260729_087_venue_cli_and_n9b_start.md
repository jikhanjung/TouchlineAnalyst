## el 범위: 같은 날·같은 장비라도 녹화가 다르면 다시 재야 한다

0392 를 0391 에서 검증된 `--el-bottom -15 --el-top 32` 로 시작했다. 4분 뒤
프리뷰(082 의 수평 확인 게이트)를 열어 보니 **틀렸다**:

- 상단 **36% 가 순수 검은 행** — 카메라가 +15.2° 까지만 담는데 +32° 를 요구.
- 아래로는 **-45° 까지 계속 경기장** — `-15` 가 근측을 크게 잘라냄.

원인: **0391 과 0392 는 다른 구장이다.** 0391=언남고등학교(붉은 트랙,
피치에 교명), 0392=**양재근린공원**. 그날 이동해서 찍었고, auto-level
pitch 도 +3° → **+21.7°** 로 크게 달랐다(카메라가 터치라인 바로 위 낮은
위치). 프리뷰 한 장이 8시간짜리 잘못된 인코드를 4분에 잡았다.

커버리지를 실측(-62..+20 렌더 후 행별 유효 폭)해 **-45..+16** 으로 확정:

| el | 유효 폭 |
|---|---|
| +16.0° | 4% (콘텐츠 상한 +17.8°) |
| +10.9° | 94% |
| -19.4° ~ -39.7° | 100% |
| -44.7° | 98% |

중앙부 근측 터치라인은 -44° 부근이라 프레임 하단으로 조금 빠지지만
그대로 두기로 함(사용자 판단). 잘못된 산출물(1.7GB 파편·프로젝트·프리뷰)
삭제 후 재시작. 6022px 폭 → hevc_nvenc, 606,229프레임(337분).

**교훈:** el 은 "직전 녹화에서 통했으니" 로 재사용하면 안 된다. 커버리지는
카메라 설치 높이·각도에 붙는 값이고, 같은 날 같은 카메라라도 옮기면 바뀐다.
프리뷰 게이트가 유일한 방어선이므로 **인코드 시작 후 첫 프리뷰는 반드시
확인**한다.

## `--venue` — 경기장 프리셋을 사이드카에 미리 기록

여태 venue(경기장 규격)는 GUI 에서 영상별로 고르는 것뿐이었다(083). 배치로
돌린 영상은 나중에 손으로 다시 골라야 해서 헤드리스에 인자를 넣었다.

```bash
python main.py --headless <L> <R> --venue 양재근린공원
python main.py --headless --list-venues     # 좌/우 없이 조회만
```

- `_seed_venue()` 가 `presets/venues.json` 의 규격을 `<pano>.ptz.json` 에
  기록 (`venue`, `field_size`, `field_circle_r`, `field_circle_auto=false`
  — GUI 의 `_apply_venue_idx` 와 동일한 키 집합).
- **이름 검증은 argparse 직후**. 오타를 수 시간 뒤에 알면 늦다.
- **`.ptz.json` 은 사용자 편집 영역이라 덮지 않는다** — 이미 다른 venue 가
  적혀 있으면 로그만 남기고 유지(`--force` 로 강제). 다른 키(번호·역할 등)
  는 병합 보존, tmp→replace 원자적 쓰기.

tests/test_headless_venue.py 7건 (프리셋 스키마 고정 + 덮어쓰기 방지 +
병합 보존 + 오타 무시 + tmp 잔재 없음). 덮어쓰기 방지 가드를 일부러 없애
테스트가 실제로 실패하는지 확인(teeth check)했다.
