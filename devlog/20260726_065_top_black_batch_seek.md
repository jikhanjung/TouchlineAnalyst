# 065: 상단 검은 경계 — 5샘플 단일 프로세스 시크

- 날짜: 2026-07-26
- 종류: 최적화 (마이너)
- 관련: [064](20260726_064_rotcam_outlier_robust_calib.md),
  [063](20260726_063_pitchwatch_fixes_and_anchors.md) (top_black 캐시)

## 변경

`measure_top_black` 이 5개 샘플을 **각각 별도 ffmpeg 프로세스**로 뽑던
걸, 다중 `-ss` 입력 + `vstack` 으로 **한 프로세스**에서 한 번에 뽑도록
(`_ffmpeg_gray_strips`). 시점마다 반복되던 프로세스 시작·초기화 비용을
제거. 실패 시 샘플별 개별(`_ffmpeg_gray_strip`)→cv2 순차로 폴백.

## 효과 (제한적)

- 결과 동일(0px), 34개 테스트 통과.
- WSL(원본이 /mnt/f, 46GB, 9p) 벤치: 15.2s → 14.3s로 **미미**. 여기선
  파일 I/O가 지배적이고, 배치도 입력이 5개라 파일 열기 자체는 5번 —
  순수 절감은 프로세스 스폰 몫뿐. native Windows 에선 프로세스 스폰
  비용이 커 좀 더 볼 수 있으나, 근본 비용은 46GB 원본의 5회 시크·읽기.
- 어차피 [063] 의 사이드카 캐시로 **파일당 최초 1회**만 도는 경로라
  실질 영향은 작다. 정확성·폴백은 유지.

## 남은 여지

더 줄이려면 샘플 수 축소(검은 경계는 스티치 고정값이라 3개로도 충분)
같은 접근이 있으나, 캐시로 충분해 보류.
