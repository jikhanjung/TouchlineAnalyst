# 095 — CI 가 devlog 088 이후 계속 빨간불이었다

2026-08-02. `Tests` 워크플로가 **10커밋 연속 실패** 중이었다. `Build` 는
계속 통과해서 눈에 덜 띄었다.

## 언제부터

```

failure  export: 인코더 파이프를 I420 직행으로     ← 여기서부터
```

devlog 085 에서 "CI 그린"을 찍고 P10 을 마감했는데, **088 이 그 상태를
곧바로 깨뜨렸고 이후 아무도 안 봤다.**

## 원인 — 빌드 의존 정량 주장을 단언했다

088 이 추가한 테스트 2건이 로컬(ffmpeg 6.1.1)에선 통과하고 CI 두 플랫폼에선
실패한다. 둘 다 **ffmpeg 빌드의 크로마 서브샘플링 필터**에 좌우되는 값이다.

| 테스트 | 단언 | Ubuntu | Windows | 로컬 |
|---|---|---|---|---|
| `test_i420_matches_the_bgr24_path` | PSNR > 40 | **39.94** | **39.39** | 40.41 |
| `test_i420_is_no_less_faithful_than_bgr24` | I420 ≥ bgr24 − 0.5 | 통과 | **−0.82** | −0.06 |

첫 번째는 문턱을 아슬아슬하게 밑돈 것이고, 두 번째가 더 중요하다 —
**"I420 이 더 충실하다"는 088 의 주장이 일반적으로 성립하지 않는다.**

088 은 실제 파노라마 프레임에서 I420 48.6dB vs swscale 44.5dB 를 재고
"손실이 없고 오히려 소폭 더 충실하다"고 적었다. 그런데 합성 프레임으로는
로컬에서도 **−0.06 / −0.10dB 로 근소 열세**고, Windows CI 빌드에선
−0.82dB 다. 우열은 콘텐츠와 빌드에 달린 성질이지 불변식이 아니다.

## 고친 것

**루마로 판정하도록 바꿨다.** Y 는 4:2:0 서브샘플링을 거치지 않으므로
빌드와 무관하게 거의 일치해야 한다 — 여기가 진짜 불변식이다. 색차는
여유 있는 하한만 본다.

```python
assert _psnr(y_a, y_b) > 44   # 로컬 47.99 — 색행렬/레인지 불일치를 잡는다
assert _psnr(a[0], b[0]) > 36 # 로컬 40.41, CI 최저 39.39
```

두 번째는 **우열을 단언하지 않도록** 이름과 내용을 바꿨다
(`test_pipe_format_does_not_change_fidelity`):

```python
assert abs(_psnr(a, img) - _psnr(b, img)) < 2.0
```

지켜야 할 성질은 "어느 쪽이 낫다"가 아니라 **"파이프 포맷을 바꿔도 충실도가
실질적으로 안 변한다"** 이다. 관측된 최대 편차는 Windows 의 0.82dB.

문턱은 전부 실측 기반으로 3~4dB 여유를 뒀다 (로컬 루마 47.99 vs 44,
전체 40.41 vs 36, CI 최저 39.39 vs 36).

## 곁들여 — `PYSTITCH_PIPE_FMT`

I420 개선폭이 **아직 A/B 로 확인되지 않았다.** 088 의 17.44fps 는 I420
적용 *전*, 다른 소재(0392)에서 잰 값이고, 오늘 20260801 은 적용 후
10.2fps 다. 소재가 달라 비교가 안 된다.

같은 소재로 재려고 `pipe_format()` 에 환경변수 오버라이드를 넣었다.
**측정 전용**임을 docstring 에 명시했다 — 상시 옵션이 아니다.

```
PYSTITCH_PIPE_FMT=bgr24   # 088 이전 동작
(미설정)                   # 현행 자동 판정
```
