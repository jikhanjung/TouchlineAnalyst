# 063: PitchWatch 버그픽스 + 이송 확정 앵커

- 날짜: 2026-07-26
- 종류: 버그픽스 + 기능 (P06-3 GUI 후속)
- 관련: [062](20260724_062_rotcam_gui_and_global.md) (rotcam GUI 구현),
  [061](20260724_061_ux_polish_and_proxy.md) (프록시/UX)

C0011(회전 카메라)·pano_5316(멀티캠 경기)로 실제 검수하며 드러난
크래시·정합·재생 문제를 잡고, 이송 검증을 앵커로 승격하는 기능을 추가.

## rotcam 캘리브 크래시 (OpenCV 5.0)

랜드마크 4번째를 찍는 순간 `cv2.solvePnP(..., SOLVEPNP_ITERATIVE)` 가
"DLT 는 6점 필요"로 예외. 필드 점은 전부 z=0 평면인데 OpenCV 5.0 이
4점 평면을 DLT 경로로 처리하려다 죽는다 (특히 3점 공선이면 평면
호모그래피 초기화가 퇴화). **평면 전용 `SOLVEPNP_IPPE`(4점부터)** 로
교체 + `cv2.error` 를 잡아 무한대 오차로 강등(크래시 대신 캘리브 없음).
합성 검증: 4/6점 모두 f·위치 정확 복원(rms 0px), 공선은 None.

## 랜드마크 클리어 잔재 → 엉뚱한 이송

"랜드마크 전체 삭제"(`_field_clear_all`)가 `field_points` 만 비우고
`field_point_frames`·`field_point_invalid`·`field_lines` 를 남겨,
클리어 후 재작업 시 **옛 프레임/옛 라인점으로 이송**돼 정합이
엉뚱해졌다 (실측: field_points 3개인데 field_point_frames 17개 잔존).
`reset_edits('field')` 와 동일 집합으로 완전 초기화 + pose 캐시 무효화.
`_field_remove_point` 개별 삭제·사이드카 없는 영상 로드 누수도 함께 수정.

## 이송 확정 앵커 (신규)

"무효(field_point_invalid)"의 **양성 짝**. 안 찍었지만 이송이 실제
라인과 맞는 프레임을 우클릭 "이 프레임 이송 전부 확정"으로 앵커 승격
(프레임 일괄). `field_point_anchors {키:[[x,y,frame],...]}` 로 사이드카
영속화.

- **엔진 중앙화** `_rc_anchor_for(k,cur)`: 각 랜드마크를 "원 배치 +
  확정 앵커" 중 **대상 프레임에 가장 가까운 소스**에서 이송. 이송·자세·
  캘리브 3경로 공통. 팬 카메라라 먼 두 프레임은 SIFT 매칭이 안 돼
  이송이 실패하던 걸, 검증된 중간 앵커가 **브리지**해 체인을 짧게.
- 스텁 검증: 배치(0)→목표(52) 직접 실패를, 앵커(50) 경유로 복구.
- 타임라인 랜드마크 레인에 확정 프레임 초록 틱.

## PitchWatch 재생/프록시

원본 승격(스크럽=프록시, 멈추면 원본 고해상도)이 안 되던 두 원인:

1. **`_ffmpeg_frame` 이 바 `"ffmpeg"` 직접 호출** — winget 설치 후 앱
   PATH 에 안 잡히면 FileNotFoundError 로 조용히 실패. `ffmpeg_bin()`
   리졸버로 통일(다른 경로는 이미 사용 중이었음).
2. **승격이 `self.mc is None` 게이트** — 멀티캠 경기(.match.json)에선
   주 카메라(파노라마)를 봐도 `_request_native` 가 아예 안 불려 실패
   메시지조차 없었다. `not mc.alt_on_main`(alt 를 메인에 띄운 동안만
   제외)으로 변경.
- 승격 요청/완료/폐기/실패 로그 추가.

## 관측성 + 열기 지연

- **로그 타임스탬프** `[HH:MM:SS.mmm]` — 단계 간 지연 측정용.
- **트랙 연결 워커 단계 로그**(공트랙/팀분류/상단경계) + 완료까지
  **대기 커서** (예외 시 done 방출로 커서 복구 보장).
- **상단 검은 경계**(`measure_top_black`): 매 열기마다 원본을 5번
  `cap.set` 순차 시크(성긴 GOP면 지점당 수 초)해 멈춘 듯했다 →
  ffmpeg `-ss -noaccurate_seek` 로 **키프레임만** 디코드(파노라마는
  카메라 정지라 어느 프레임이든 경계 동일) + **사이드카 캐시**(영상
  고정값이라 1회만 측정, 이후 열기엔 생략).

## 파노라마 마커 색

파노라마(고정 뷰)에서 랜드마크가 일부 청록·나머지 회색으로 보인 건,
회전 카메라용 "프레임-스테일" 색칠(찍은 프레임에서 1초 넘으면 회색)이
그대로 적용된 잔재. 파노라마는 프레임 무관하게 위치가 같으니 전부
청록으로 통일.

## 상태

전부 실데이터(C0011·pano_5316)로 확인. rotcam 확정 앵커의 실제 브리지
효과(특정 프레임 SIFT 실패 케이스)는 Windows 재검수 대기.
