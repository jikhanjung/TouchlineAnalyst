# 070: 랜드마크 드래그 라이브 재피팅 (rotcam)

- 날짜: 2026-07-26
- 종류: 기능 + 버그픽스
- 관련: [069](20260726_069_rotcam_radar_projection.md), [064](20260726_064_rotcam_outlier_robust_calib.md)

## 배경

사용자: "랜드마크를 드래그해서 옮기면 경기장 그리는 게 바로바로 다시
그려져?" — 확인해보니 둘 다 아니었다:

1. **드래그 중**: 마커만 이동, 라인은 안 바뀜 (의도 — 파노라마 TPS
   재피팅이 무거워 놓을 때만).
2. **놓을 때 (버그)**: 재캘리브는 하는데 `_rc_pose_gen` 을 안 올려
   rotcam 라인이 **드래그 전 자세 캐시로 계속 그려짐** — 놓아도 라인이
   안 움직였다.

## 구현

- **릴리스 버그**: 랜드마크 드래그 릴리스에서 pose gen 무효화 추가.
- **라이브 재피팅**: rotcam 은 드래그가 프레임을 안 바꿔 H 캐시가 다
  살아 있다 — 재피팅 비용은 RANSAC+f 스캔뿐. `calibrate_reference` 에
  `f_hint` 추가: 직전 f ±15% 만 좁게 탐색(steps 7, 황금 12) →
  **138ms → 17ms**. 드래그 틱에서 150ms 스로틀로
  `_refit_field_rotcam(live=True)` + pose gen 갱신 → 경기장 라인이
  드래그를 따라 라이브로 움직인다. 전 범위 탐색은 놓을 때(정확도 복원).
- 드래그 중 어정쩡한 위치는 RANSAC 이 이상치로 걸러 라인이 널뛰지
  않는다. live/full 결과 f 일치(±2%) 합성 확인, 테스트 9개 통과.

## 참고 (같은 스크린샷에서 확인된 것)

- 거울해 수정(069) 실전 확인: C0011 상태줄 설치 z=+5.0m 물리해, 레이더
  피치 전역 정상 ("레이더는 잘 나오는 것 같아").
- 엔드라인 어긋남은 가까운 왼쪽 코너 미지정 상태 — 라이브 재피팅으로
  코너 찍고 끌며 맞추는 워크플로우가 이제 가능.
