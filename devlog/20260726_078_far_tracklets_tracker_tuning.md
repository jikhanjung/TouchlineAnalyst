## 원경 타일 검출 → 트랙릿 (사용자 방향)

077 의 타일 사람 검출(tid=-1)은 표시용이었는데, 목적은 **트랙릿/팀분류**
— ByteTrack 은 메인 패스 내부라 타일 검출을 못 받는다. `_FarTracker`
미니 트래커(최근접 연결) 추가: 원경은 샘플 간 이동이 작아(0.1s 에
~10px) 충분하다. tid 800001+ (ByteTrack 소형 정수·수동 900000+ 와
분리) → 스팬·세그먼트·팀분류(HSV)·병합·번호가 전부 tid 기반이라
그대로 참여한다.

- 연결 반경 = 파노라마 폭 0.8% (6540px→52px), 2초 놓치면 종료.
- 테스트 5개 (tests/test_far_tracker.py) — **만료 정리를 매칭 뒤에
  하던 버그를 테스트가 잡음** (오래 사라진 트랙이 같은 자리 새 사람에
  재사용) → 매칭 전 정리로 수정.

## 트래커 튜닝 (presets/tracker_pano.yaml)

"object tracking 이 더 잘 되면 좋겠다" — 기본 botsort.yaml 은 움직이는
카메라 가정 + ReID 꺼짐. 정적 파노라마용 튜닝:

- `gmc_method: none` — 고정 카메라라 전역 움직임 보상은 비용만.
- `track_buffer: 60` — detect_every=3(체감 10fps)에서 기본 30=3초는
  가림에 짧다. 6초로 재획득 창 확대 (트랙릿 파편 감소 — pano_5316 은
  ~25명에 트랙릿 2047개였다).
- `with_reid: true, model: auto` — 검출기 특징 외형 ReID 로 교차/재진입
  ID 스왑 감소. 저문턱(0.1)과 ByteTrack 2단 연결 시너지.

analyze_video 가 presets 파일 존재 시 자동 사용 (tracker_cfg 로 재정의
가능), 체크포인트 키에 트래커명 포함. ultralytics 8.4.101 로드 스모크
확인. 테스트 151 통과.

## 남은 개선 지렛대 (미적용)

1. **detect_every 3→2/1** — 연결 품질에 가장 큰 단일 지렛대, 분석 시간
   비례 증가.
2. 모션 연속성 기반 **자동 트랙릿 스티칭** 후처리 (지금은 ReID 라이트
   '제안' + 같은 번호 병합만).
3. det_w 상한 상향 (해상도 ↑, 시간 ↑).
