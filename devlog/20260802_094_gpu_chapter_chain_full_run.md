# 094 — GPU 경로 챕터 체인 + 한 챕터 전체 실행

2026-08-02. devlog 093 의 프로토타입은 첫 챕터만 열 수 있어 60프레임(2초)이
한계였다. 챕터 체인을 붙이고 **17,000프레임(9.5분, 챕터 경계 통과)**을 돌렸다.
짧은 테스트로는 절대 안 걸렸을 함정을 하나 잡았다.

## 결과 요약

| 항목 | 결과 |
|---|---|
| 완주 | 17,000프레임, 챕터 경계 통과 (재오픈 2회) |

GPU 쪽만 **NVENC 인코딩까지 포함**한 수치다. 이번엔 머신이 유휴 상태였다.

## `ChapteredGpuReader` (`scripts/gpu_chapters.py`)

`cudacodec` 은 파일 하나만 열 수 있어 GoPro 챕터 체인을 못 잇는다.
`ChapteredVideo` 와 같은 인터페이스(`seek_frame`/`read`/`position`)로 감쌌다.

- 프레임 수는 CPU 로 1회만 조사 (`CAP_PROP_FRAME_COUNT`, 디코드 없음)
- 전역 프레임 → (챕터, 로컬) 변환 후 `firstFrameIdx` 로 오픈
- `nextFrame()` 이 False 면 다음 챕터를 열어 재시도

**경계 비트정확 검증** — 전역 프레임을 (챕터, 로컬)로 풀어 ffmpeg 으로 뽑은
원시 Y 와 바이트 비교:

```
전역 15958 → 챕터 0 로컬 15958: 비트정확 일치   [재오픈 1회]
전역 15959 → 챕터 0 로컬 15959: 비트정확 일치   [재오픈 1회]
전역 15960 → 챕터 1 로컬     0: 비트정확 일치   [재오픈 2회]
전역 15961 → 챕터 1 로컬     1: 비트정확 일치   [재오픈 2회]
```

프레임을 흘리거나 겹치지 않는다. 경계 비용은 실측 **약 12초** — 해당
1000프레임 구간만 22.9 → 17.93 fps 로 떨어졌다가 복귀한다. 093 에서 잰
재오픈 231~318ms 보다 큰데, 한도를 올린 디먹서가 패킷을 더 훑기 때문으로
보인다. 8챕터 3.6시간 스티칭이면 총 ~84초, **0.6%** 라 무시 가능하다.

## ⚠️ 함정 — 디먹서가 조용히 끊는다

첫 실행이 10,973프레임에서 멈췄다. 챕터 경계는 **정상적으로 넘었고**
챕터 1 에서 약 30프레임 뒤에 죽었다.

```
grabFrame packet read max attempts exceeded (current value is 4096)
```

단독 재현:

| `OPENCV_FFMPEG_READ_ATTEMPTS` | `GP010001.MP4` |
|---|---|
| 기본 4096 | **30프레임** |
| 1,000,000 | 400프레임 (테스트 상한까지) |

GoPro 챕터는 스트림이 **5개**다 (video, aac, data×3 — GPMF 포함).
cudacodec 의 FFmpeg 디먹서가 비디오 패킷을 찾다 4096회에서 포기하는데,
**그때 `nextFrame()` 이 내는 False 가 정상 EOF 와 구분되지 않는다.**

프로덕션에 이대로 들어갔으면 **오류 없이 잘린 파노라마**가 나왔을 것이다.
게다가 챕터 0(`GOPR0001.MP4`)은 같은 스트림 구성인데도 10,944프레임을
멀쩡히 넘겼다 — 파일마다 인터리빙이 달라 **짧은 테스트로는 안 걸린다.**
한 챕터 전체를 돌린 게 이걸 잡았다.

`gpu_chapters.py` 가 import 시점에 한도를 올린다 (`cv2` import 보다 먼저
잡혀야 해서 순서에 주석). 정식 채택 시 **끊긴 이유를 EOF 와 구분하는 검사**
(기대 프레임 수 대비 실제 디코드 수)를 반드시 같이 넣어야 한다.

## 남은 것

- **색변환** — PSNR 40.6dB 차이 그대로. `NV_YUV_SURFACE_FORMAT` + 자체
  BT.709 풀레인지 변환. 팀 분류가 색 기반이라 영향 확인 필요
- **세그먼트 전환** — `export_pano` 는 세그먼트마다 렌더러를 바꾸는데
  프로토타입은 세그먼트 0 고정
- **`refine_seam`** — 프로덕션은 부르고 프로토타입은 건너뜀
- **끊김 검출** — 위의 디먹서 함정 때문에 필수
- **Windows 적용** — win wheel + CUDA Toolkit 13.1
- **`render.py` GPU 경로 + CUDA 미설치 폴백** — `pitchstitch.py` 가 torch
  없이 기동하는 것과 같은 원칙

## 스크립트 버그 2건 (수정함)

- CPU 기준선과 GPU 루프가 **변수 `i` 를 공유**해 비교 배율이 엉터리로
  나왔다(`처리량 0.04x`). GPU 루프가 `i` 를 17000 으로 덮어써 CPU 프레임
  수가 17000 으로 계산됐다 → `n_cpu` 로 분리
- 출력 일치도 비교가 CPU 표본 마지막(300)과 GPU 마지막(17000)을 비교하고
  있었다 → **같은 프레임 번호**를 잡도록 수정
