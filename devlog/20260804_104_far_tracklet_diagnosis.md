# 104 — 원경 파편화 진단: 트래커가 아니라 유령 검출이었다

2026-08-04. TODOs #1 은 "검출은 잘 되는데 이어 붙지 않는다"였다. 재분석 없이
캐시·원본만 읽어 재보니 **전제가 틀렸다.** 가설 세 개를 실측으로 기각하고,
문제가 트래커 파라미터가 아님을 확인했다. 요약 단계 필터로 트랙릿을
**82% 줄이면서 관측은 82% 유지**한다.

## 기각한 가설

| 가설 | 실측 | 판정 |
|---|---|---|
| 매칭 반경(48px)이 좁다 | 원경 선수 실제 이동 **샘플당 0.5px** (75% 1.2, 95% 10.1) → 48px 는 **9.4초분** | ❌ |
| 만료(2초)가 짧다 | 끊긴 뒤 48px 안에서 재시작 **1.8%**, 2샘플 창에선 **0.0%** | ❌ |
| 짧은 트랙 = 잔디가 배어든 작은 검출 | 단발이 오히려 **더 큼** (h 45.2 vs 50샘플+ 34.8px) | ❌ |

특히 "끊긴 뒤 가장 가까운 새 트랙까지 거리"가 **간격과 무관하게 평평**하다:

| 간격 | 0.3~0.5초 | 0.6~1초 | 1~2초 | 2~4초 | 4~6초 |
|---|---|---|---|---|---|
| 거리 중앙 | 137px | 170px | 174px | 179px | 172px |

같은 선수가 멀어진 거라면 간격에 비례해야 한다. 평평하다는 건 그 150px 가
**원경 선수 간 평균 간격**일 뿐이라는 뜻이다 — **반경을 넓히면 회수가
아니라 ID 뒤바뀜이 난다.**

## 진짜 문제 — 계수 착시

| 트랙 길이 | 트랙 수 | **관측 점유율** |
|---|---|---|
| 단발 | 31.7% | **2.7%** |
| 2~3샘플 | 22.9% | 4.6% |
| 4~10샘플 | 23.5% | 12.3% |
| **11샘플(1.1초)+** | **21.9%** | **80.5%** |
| 50샘플(5초)+ | 4.8% | 49.0% |

트랙의 **절반 이상이 관측의 7.3%** 만 나른다. 검출 스트림은 샘플당 5.90개
중 **4.75개가 1.1초 이상 지속하는 트랙**에서 온다 — 데이터 자체는 안정적이다.

"트랙릿 21만 개"는 짧은 유령이 개수를 부풀린 것이었다. `conf_far=0.1` 이
만든 꼬리로 보인다: 트랙이 짧을수록 토르소 색이 **단조롭게** 잔디 쪽으로
이동한다 (단발 H57.5/S49.3/V124 → 50샘플+ H103.7/S30.1/V105).

## 고친 것 — 요약 단계 필터 (비파괴)

분석 원본(`.analysis.json`)은 건드리지 않는다. 문턱은 언제든 바꿀 수 있고
재분석 100시간이 필요 없다.

```python
FAR_MIN_OBS_SEC = 1.0                      # PYSTITCH_FAR_MIN_SEC 로 재정의

```

적용 지점 둘:

  (하나만 거르면 KeyError). 캐시 키에 문턱을 넣어 문턱 변경 시 무효화
- `team_features` — 팀 색 군집 투표에서도 뺀다 (유령이 군집을 흔든다)

**근경은 길이와 무관하게 남긴다.** 근경은 이미 건강하고(수명 8.5초, 단발
6.4%), 짧은 근경은 사용자가 실제로 보고 다루는 대상이다.

  올리려면 재분석이 필요하고 회수/손실을 따로 재야 한다.
